# Terraform Plan Lens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A VS Code extension that runs or loads a Terraform plan and shows it on the code (gutter, block band, end-of-line hint, hover) and in a Sixth-styled sidebar webview.

**Architecture:** Pure model modules (`planParser`, `hclScanner`, `matcher`, `envs`) with unit tests and no `vscode` import; a `runner` that spawns terraform; editor glue (`decorations`, `hover`), a webview provider and a status bar wired in `extension.ts`. One in-memory `PlanStore` is the single source of state.

**Tech Stack:** TypeScript 5, esbuild 0.24 (cjs, node18), `@types/vscode ~1.85`, `node --test`, playwright-core 1.47.2 (render checks), codicons vendored from joblauncher.

**Spec:** `docs/superpowers/specs/2026-10-28-plan-lens-design.md` (+ mockup `2026-10-28-plan-lens-mockup.html`)

## Global Constraints

- Node 18.19 on WSL; engines `vscode ^1.85.0`; esbuild target `node18`; publisher `jay-boo`, name `tf-plan-lens`, displayName `Terraform Plan Lens`.
- Never run `apply`, `destroy`, `import`, `state` or any write command. Only `init`, `plan`, `show -json`.
- `TF_DATA_DIR` = `<globalStorage>/<sha1(root) first 12>/<env with / → _>`; the user's `.terraform` is never touched.
- Plan binary in a fresh `fs.mkdtemp(os.tmpdir()/plan-lens-)` folder, removed after `show -json` in `finally`.
- No hex colours in extension CSS or decoration code: theme vars / contributed colour ids only (`planLens.create` → `testing.iconPassed`, `planLens.update` → `charts.yellow`, `planLens.replace` → `charts.orange`, `planLens.destroy` → `errorForeground`, `planLens.read` → `charts.blue`). Gutter SVGs are the only exception (one file per action × light/dark).
- Sixth v2 rules: 13px body, names `--pl-bright`, secondary 12px muted, mono only for attributes/addresses, `--pl-border` on every outlined/filled element. Look = the mockup.
- Severity order: destroy > forget > replace > update > create > read > noop.
- Settings: `planLens.environmentGlob` (default `environments/**/terraform.tfvars`), `planLens.root` (default ""), `planLens.terraformPath` (default `terraform`), `planLens.showUnchanged` (default `true`).
- Packaging: `node -r ./scripts/file-shim.cjs ~/projects/gitland/node_modules/@vscode/vsce/vsce package --no-dependencies --allow-missing-repository`, shim = `globalThis.File ??= require("node:buffer").File;`.

## Review Focus

- **CRLF `.tf` files** (repo is edited from Windows): scanner line numbers must stay right → scanner test with `\r\n`.
- **Folder names with `%20` and spaces** (`Infra%20-%20Terraform…`): always use `uri.fsPath`/`vscode.Uri.file`, never string-built URIs; spawn with args array (no shell) → envs test with that path; runner arg test.
- **Whole-object sensitive** (`after_sensitive: true`, `before_sensitive: true`) and nested sensitive maps → parser test: every attr shows `(sensitive)`, no value leaks.
- **Plan older than the code** (block renamed/removed after the plan): change becomes an orphan, no crash, no mark on a wrong block → matcher test.
- **Root module resources in several files and same type/name in two modules** (`this` everywhere): must match only inside the module's folder → matcher test.
